## Unreleased

### Added

- Agentic-readiness scaffolding: `CLAUDE.md` constitution, a canonical
  `make gate`, two committed public-surface goldens, real tests, and CI.
- `api/public-surface.txt` — the public Dart surface (every public member **and
  parameter name**), generated by `tool/api_dump.dart` and diffed by the gate.
- `api/js-interop-surface.txt` — the `window` function names this package
  resolves **by string** at runtime (`initiateAuth`, `verifyAuth`,
  `startHeadless`, `openLoginPage`, and the `getResponse` slot it installs).
  These are implemented in the `vegapunk` repo and shipped as
  `https://otpless.com/v2/flutter.js`; nothing in either repo fails to compile
  if one is renamed, so they are now pinned like a reflection contract.
- `analysis/analyzer-baseline.txt` + `scripts/check-analyzer-baseline.sh` —
  `flutter analyze` with errors and warnings fatal, plus a diff of the info list
  so a new lint or deprecation fails the gate. Nothing is suppressed: the
  `dart:html` / `dart:js` deprecations stay visible because this package needs a
  `package:web` + `dart:js_interop` rewrite.
- `Makefile` — `make gate` is now the single definition of "verified".
- `README.md` rewritten: it was the pub.dev boilerplate comment block plus an
  integration snippet, titled "Flutter". It now documents the API as a table,
  the response shape, the native-divergence warning, a Troubleshooting section
  for the three known defects, and the development workflow.
- `.github/workflows/build-test.yml` (runs `make gate` on PR and push to main)
  and `.github/workflows/atlas-docs.yml` (wires platform docs to the private
  `otpless-tech/atlas` repo).
- PR template with the constitution checklist and a parity statement line.

### Fixed

- **The committed test suite did not run.** `flutter test` failed to *load*
  (`dart:html` / `dart:js` cannot compile on the Dart VM) and `flutter test
  --platform chrome` failed all 3 tests: they asserted `window.getResponse` was
  registered, but the JS globals they depend on were never stubbed, so
  `js.context.callMethod` threw before registration could happen.
- The suite is now 11 tests that pass on Chrome and assert the actual marshalled
  payloads (`channel` injection per method, `verifyAuth` adding none), the
  callback wiring, and the `ONETAP`-only filter in `verifyAuth`.

### Documented, not fixed — see CLAUDE.md "Known defects"

Each is pinned by a characterisation test that asserts the wrong behaviour on
purpose, so fixing it fails the gate loudly rather than silently changing
merchant-visible behaviour:

1. `executeFunction` is `async` returning `void`, so a call made before the
   browser bundle loads routes its `NoSuchMethodError` to a Zone nobody listens
   to **and** never registers the result callback. Merchant symptom: nothing
   happens, forever, with no error.
2. `getResponse` is a single global slot — concurrent requests cross callbacks.
3. `verifyAuth` forwards only `responseType == "ONETAP"`, so a wrong-OTP
   `FAILED` response never reaches the caller through `verifyAuth`.

### Removed

- `example/build/` — compiled Flutter output that had been committed. Now
  gitignored.

### Not changed, deliberately

- The version stays at `1.2.6`. Publishing is an owner decision (see below).
- The `sdk: ">=2.13.0 <4.0.0"` constraint is untouched; raising it would narrow
  who can install the package. This is why `tool/api_dump.dart` uses `dart:io`
  only instead of the `analyzer` package.
